## Error integration (from `wtp-e-errors.xlsx`)

**Interpretation note — rough estimates, not exact accounting.** These error counts
are a general approximation: transient errors, run restarts, graph-structure changes,
and cleanup/rerun cycles skew the numbers, and some errors cannot be fully attributed.
Do not expect them to sum exactly against run totals. Note also that `effective_runs` comes from a separate source (dataset row counts) and does NOT include the error count — it is unrelated to and unadjusted by the `errors`/`total_incl_errors`/`error_pct` columns. They remain a valid directional
indication of which models have major issues generating valid tokens that can be
parsed consistently and correctly. Future runs will capture exact values.


Columns `errors`, `total_incl_errors`, `error_pct` were merged in from the monitoring
error export (`experiments/wtp/wtp-e-errors.xlsx`): non-transient pipeline errors per
provider × state (rate-limit/429/insufficient noise already excluded by the source
query). Mapping per `experiments/wtp/wtp-errors-experiment-mapping.csv` (state_id →
version). `total_incl_errors = rows + errors`; `error_pct = 100 × errors /
total_incl_errors`.

Caveats:
- `v6.3-db-syn-gpt-beliefs` and `v6.2-db` error counts come from states that are
  **supersets** of the published runs (unpublished/partial runs share the state), so
  those `error_pct` values are upper bounds (medium-confidence mapping).
- `v4.0-db`, `v6.0-db`, `v6.0-do`: no error states exist — zero non-transient errors.
- Not mapped to line items (different pipeline stage): the seven
  `synthetic beliefs - <model>` belief-generation states (166 errors total: flash-lite
  112, kimi-k2 20, deepseek-r1 12, gpt-5-mini 10, gemini-2.5-flash 8, deepseek-chat-v3.1 2,
  mistral-medium-3.1 2 — inputs to `v6.3-db-syn-multi-1:1`), and 473 unattributed errors.
